# Native menus (T07)

The common build_menu(Store, MenuKind, MenuSettings) is a read-only SQLite projection under one deferred read transaction. It returns immutable stable-ID commands and data_revision. Native adapters do not query SQLite or repeat history/snippet grouping. Projection is bounded to8MiB metadata /1000 history rows /1000 folders /10000 snippets. Only bounded text prefixes are loaded, not full image/PDF payloads. UTF-8 and UTF-16 titles are sanitized, trimmed, first-line/grapheme-limited using pinned Unicode17 libgrapheme3 character segmentation. Tooltip text preserves line breaks. Native labels escape platform mnemonic characters. Disabled/obsolete native nodes do not trigger replacement items.

Menu settings retain inline0(0-100), folder10(1-100), title20(1-1000), tooltip200(1-10000), numbering1-based on, numeric selection off, snippets below. First ten shortcuts map1..9,0 or0..9. Generic image/format references are metadata; menu_preview accepts only bounded ready-made RGBA<=512x512, fits configured bounds, and can generate hex swatches. T12 still owns image decode/thumbnail generation. libgrapheme char-only adaptation omits unused word helper for MSVC link compatibility; upstream files, hashes and ISC/Unicode notices remain in third_party/libgrapheme.

NativeMenu must be initialized/updated/dispatched/destroyed on its owner GUI thread (main thread on AppKit). process_events is a bounded integration helper; production can use the corresponding platform main loop. It provides native popup, standard/reversed/hidden tray and an always-visible launcher. native_handles are borrowed diagnostics/embedding handles invalidated by update/destruction. Invocation target/activation token is preserved in returned MenuCommand; no paste, focus injection or token consumption occurs in T07. Controller must validate_menu_command before selection. execute_menu_clear validates revision and deletes atomically under BEGIN IMMEDIATE; Quit/settings/editor are not blocked by unrelated history revisions.

- macOS: NSMenu/NSStatusItem, native labels/tooltips/SF Symbols/RGBA, standard template icon follows appearance. Regular application with visible launcher window, independent of status-item availability.
- Windows: TrackPopupMenuEx, Shell_NotifyIcon and TaskbarCreated re-registration, native bitmap menu items/tracking tooltip, PerMonitorV2 layout and preview raster rescaling at DPI changes. System menu text/navigation/accessibility remain native; no custom web view.
- Linux: GTK3 popup/MenuButton and StatusNotifierItem + com.canonical.dbusmenu over session bus. No GtkStatusIcon. Watcher absence/restart is explicit and launcher stays available. DBusMenu hosts may ignore preview icons/tooltips; owned GTK popup retains both. Native Wayland placement is anchored to a real launcher/button input event. A D-Bus activation without a current input event presents the launcher instead of pretending to have arbitrary pointer positioning/focus. Activation token is passed to controller for later integration, never forged.

The cliptiq_menu_host executable is a review host, not the finished product: `--demo`, `--database PATH`, `--history`, `--snippets`, `--no-tray`. Optional `--capture` composes the existing platform clipboard session against an explicit database; default/--smoke never access clipboard. History revisions refresh the model; Clear is functional. Selection returns a command only; clipboard writes/auto-paste/modifiers are T08. Settings/editor remain disabled in review host until T09/T10. Snippet rows use T02 schema order; enabled flags/editor CRUD are T10, not invented here.

Tests use private Xvfb/headless Sway/session bus, an independent watcher/DBusMenu client and an isolated Win32 station. macOS native tests run only on hosted macOS. These do not close manual app-to-app T04-T06 or interactive T07 keyboard/screen-reader/desktop acceptance. See tests/manual/menu.md. Binary probes are baseline capture-capable history host -> shared menu/Unicode -> native menu; dynamic GUI runtime closure is separate from executable bytes.

Invocation contexts are scoped to one popup opening, consumed on selection and cleared on cancellation; independent status/MenuButton/DBusMenu routes cannot reuse a prior target/token. Windows keyboard/DPI/context test library replaces only the modal popup boundary; production uses TrackPopupMenuEx. AppKit context regression replaces only its modal boundary. Windows generic type icons/options parity is a deferred Minor; previews/swatches work. X11 supplied coordinates are honored; Wayland no-input route discards context and presents launcher.
