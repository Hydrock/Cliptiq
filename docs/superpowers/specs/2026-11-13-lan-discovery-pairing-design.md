# Поиск устройств Cliptiq и сопряжение по коду

Статус: предложение для согласования, реализация не начата.

## Задача и согласованные решения

Пользователь хочет нажать «Найти устройства в сети», увидеть компьютеры с
Cliptiq и подключить выбранный без ввода IP, портов и длинного ключа.
Ручное подключение сохраняется, но сворачивается под отдельной кнопкой.
Пользователь выбрал mDNS/Bonjour и сопряжение одноразовым кодом.
Текущий рабочий LAN-обмен, история и существующие пары сохраняются.

Основные платформы этой задачи: macOS и Windows, одинаковый сценарий.
Linux сохраняет работающие ручные подключения; интерфейс обнаружения должен
иметь явное состояние «недоступно», если системной службы нет. Реализация
Linux-адаптера через Avahi может быть отдельным этапом, без блокировки Mac/Windows.

## Рассмотренные подходы

1. Выбранный: DNS-SD/mDNS, системные DNSService API на macOS и DnsService API
   на Windows. Нет перебора адресов подсети и отдельной установки Bonjour на Windows.
2. Собственные UDP-запросы/ответы: потребовали бы отдельного протокола обнаружения,
   обработки нескольких интерфейсов и дополнительной совместимости. Не выбран.
3. Только заполнение адресов, со старым длинным ключом: пользователь предпочёл
   законченный сценарий сопряжения по коду.

## Сценарий пользователя — предложение

Вкладка «Сеть»:

- Имя этого компьютера и переключатель «Доступен для обнаружения».
- Кнопка «Найти устройства в сети», состояния поиска/остановки/повтора.
- Список: имя устройства, система, состояние, действие «Подключить».
- Ниже уже подключённые устройства: подключено/недоступно, отправка/приём,
  отключить и забыть. Повторный поиск не создаёт дубликаты существующих пар.
- Раздел «Подключить вручную» свёрнут по умолчанию. В нём прежние адрес, порт,
  ключ и дополнительные параметры слушателя. Существующие поля не удаляются.

Поиск работает только по явному нажатию кнопки, ограниченное время (10 секунд),
с возможностью остановки. Найденные результаты не сохраняют новую пару сами.
Первоначально доступность для обнаружения выключена, включая обновление старых
профилей: существующий обмен продолжает работать без новой сетевой публикации.
Чтобы новый компьютер нашли, на нём один раз включают доступность. Это явная
настройка, а не скрытый побочный эффект открытия вкладки.

После выбора B на A устройство B показывает запрос от A. Пользователь B
разрешает сопряжение и получает случайный шестизначный код на экране B.
Пользователь вводит его на A. Код действует 120 секунд, не сохраняется и не
копируется приложением в буфер. Успех добавляет пару на обоих компьютерах.
Отказ/отмена/таймаут не подключают устройства и не передают содержимое буфера.
Повторное сопряжение требует нового кода. После успеха переподключение автоматическое.

## Обнаружение и сеть

Объявляется только сервис Cliptiq, например _cliptiq._tcp.local.; TXT содержит
версию протокола, device_id и короткое имя/тип системы. Это публичная информация
для локальной сети, не секреты, история, открытые окна или приложения.
Сервис указывает на отдельный управляющий TCP-слушатель сопряжения, а не на
существующий TLS-PSK-слушатель данных. Его порт выбирается ОС и передаётся DNS-SD.

Объявление работает, пока приложение запущено и включена доступность, независимо
от наличия сохранённых пар. Без этого новый компьютер сейчас не смог бы появиться:
существующий LAN-сервис запускается только при активных настроенных соседях.
Выключение доступности закрывает управляющий слушатель и снимает публикацию,
но не разрывает существующие доверенные пары и не выключает обычный обмен.

Для новой автоматической настройки выбирается подходящий локальный интерфейс
по маршруту к найденному соседу; IP/порты заполняются автоматически. Имеющийся
пользовательский bind-адрес не переписывается молча. Если несколько сетей нельзя
обслужить текущим одним слушателем, предложить выбор сети по имени интерфейса,
без ручного IP. Поддержка нескольких одновременных слушателей не входит в v1.
Публикация и принимаемый адрес должны соответствовать выбранной сети.

Для уже настроенной пары найденный device_id может обновлять адрес только после
проверки обычным аутентифицированным TLS-соединением. Объявление само не является
доказательством личности и не заменяет привязанный remote_device_id или ключ.
В VPN/изолированном Wi-Fi обнаружение может отсутствовать; ручное подключение остаётся.
Брандмауэр, VPN и маршруты автоматически не изменяются.

На macOS добавить NSLocalNetworkUsageDescription и точный тип NSBonjourServices.
Разрешение локальной сети запрашивается при включении доступности/поиске,
а не в обязательном стартовом окне буфера/вставки. Отказ не блокирует Cliptiq.
На Windows использовать штатные API Windows 10+, не устанавливать службу Bonjour.

## Сопряжение и защита ключа

Короткий код не становится TLS-PSK и не отправляется по сети как пароль.
Предложение исполнителя: PAKE через готовую EC J-PAKE реализацию уже закреплённого
Mbed TLS 3.6.7 (P-256/SHA-256). В библиотеке API допускает использование обмена
вне TLS. Добавить только нужный модуль, не включать TLS 1.2 или незащищённый режим.
До реализации проверить совместимость минимальной конфигурации и библиотечные
тестовые векторы. Если готовый модуль не подходит, вернуться к дизайну, не писать
собственную замену PAKE и не передавать постоянный ключ поверх обычного TCP.

Из результата PAKE через HKDF-SHA256 получают отдельный случайный по стойкости
256-битный ключ пары. Контекст включает версию, обе роли/device_id, свежие nonce
и хеш полного обмена. До принятия ключа нужны взаимные подтверждения владения
ключом с привязкой к тому же контексту; существующий TLS 1.3 PSK/ECDHE канал данных
после этого не меняется. Формат кадров и порядок transcript фиксируются отдельным
протокольным описанием и тестовыми векторами до написания транспортного кода.

На B допускается только одна активная попытка с кодом. Неверный код завершает
попытку; максимум 3 попытки за срок кода, затем код аннулируется. Ограничить также
общую частоту запросов, число соединений, размер кадров и время бездействия.
Ограничения не должны обходиться простым изменением заявленного device_id.
Имена и TXT-поля недоверенные: ограничить размер, проверить UTF-8, исключить
управляющие символы в отображении. Не доверять адресу/имени из TXT вместо адреса
разрешённого DNS-SD сервиса и реально установленного соединения.

Постоянные ключи — только Keychain/Credential Manager/Secret Service. Запись пары
проходит явные состояния подготовки/подтверждения; до взаимного подтверждения
пара не считается активной и не обменивается буфером. При сбое записи или обрыве
UI показывает незавершённое подключение, позволяет безопасно повторить/отменить;
стадированные секреты очищаются при отмене/истечении. Нельзя обещать атомарную
запись двух отдельных компьютеров: протокол обязан обрабатывать односторонний
успех и потерю последнего ACK идемпотентно. Успешный TLS handshake обоих готовых
участников — условие начала передачи буфера.

## Интеграция и совместимость

Общие контроллеры discovery/pairing, поддельные адаптеры для unit-тестов,
асинхронные системные адаптеры и существующие native-окна. GUI-поток не ждёт сеть.
Состояния поиска, кодов и запросов обновляются существующим pump/poll.
Смена/закрытие окна не сохраняет черновик и отменяет незавершённую попытку;
постоянная доступность следует сохранённому переключателю, а не жизни окна.

Данные старых пар мигрируются без смены device_id, ключей и направления обмена.
Ручной сценарий остаётся совместим с прежними версиями Cliptiq; старые версии
без публикации не появляются в поиске. Подключение по IP остаётся для таких версий.
Правила захвата, поддержанные форматы, отсутствие выгрузки старой истории,
сниппетов и автоматической вставки при сетевом получении не меняются.

## Проверка готовности

- Обнаружение двух инстансов, дубликаты, одинаковые имена, исчезновение устройства,
  отсутствие самого себя, отмена/повтор поиска, просроченные объявления.
- Поиск доступен до настройки первой пары; при выключенной доступности публикации нет.
- Верный/неверный/просроченный код, отказ на B, повторное сопряжение и ограничения.
- PAKE-векторы, подмена transcript/device_id, MITM/повтор кадров, потеря ACK,
  обрыв и отказ системного хранилища; секретов в БД/логах/объявлениях нет.
- Native UI macOS и Windows: поиск, список, запрос/код, состояние пары и
  свёрнутый ручной ввод; EN/RU; ранее сохранённые настройки не теряются.
- Реальный Mac ↔ Windows: найти друг друга без адресов, подтвердить код, получить
  новый текст/изображение, переподключиться после перезапуска и смены адреса.
- Если в этой среде нет Windows, явно передать Windows-проверку, не заявлять её
  пройденной по одним Mac-тестам. Обычный LAN и fullscreen-меню не должны регрессировать.

## Источники и решения исполнителя

API Windows: https://learn.microsoft.com/en-us/windows/win32/api/windns/nf-windns-dnsservicebrowse
API/разрешения macOS: https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy
PAKE API: закреплённый include/mbedtls/ecjpake.h, версия 3.6.7.

Срок поиска 10 секунд, длина кода 6 цифр, срок 120 секунд, интерфейс выбора сети,
стадирование записи и выбор EC J-PAKE — предложения исполнителя, а не отдельные
требования пользователя. Конкретные размеры/лимиты и схема миграции остаются
для плана, в пределах описанного поведения и существующих ограничений LAN.
