# Установленная сборка: замер на разблокированном экране

13 ноября 2026, Windows 11 x64, 32 логических CPU. Установлена сборка исходников `28888aa`, SHA-256 `1a43080be204dab70dd0f0ed7668b085b1cc7b8eff809e7618f78d599d63dde8` в `%LOCALAPPDATA%/Programs/Cliptiq/Cliptiq.exe`. Прежний EXE, build-info и SQLite backup истории сохранены в `%LOCALAPPDATA%/Cliptiq/backups/cpu-optimized-*`.

Настоящий пользовательский профиль: 30 записей, LAN включён; после замеров интерфейс подтвердил подключение Mac по TLS 1.3. Ревизия базы оставалась 302, число записей — 30. Содержимое буфера не читалось измерителем. Сборка/CTest одновременно не выполнялись. CPU измерен относительно одного логического ядра; память — средняя по выборкам раз в секунду. Working set включает разделяемые резидентные страницы; private bytes — приватный commit, не отдельная добавка к working set.

| Состояние | Интервал | CPU одного ядра | Working set, МиБ | Private bytes, МиБ |
|---|---:|---:|---:|---:|
| Фон, нет открытых окон | 60 с | 0.052% | 31.40 | 9.52 |
| Главное окно на переднем плане, исходный фокус | 60 с | 12.630% | 33.79 | 10.94 |
| Диагностика после Ctrl+F, фокус в фильтре | 15 с | 0.521% | 33.93 | 10.95 |

Основные режимы измерены по минуте после 10-секундного прогрева. Перед отдельным foreground-замером окно явно активировано и визуально проверено на разблокированном экране. Предварительный смешанный интервал открытия/активации дал 13,07% ядра; он не включён в таблицу. Повторный отдельный foreground-интервал сохранил высокую нагрузку, поэтому это не только стартовый всплеск.

После Ctrl+F короткая диагностическая выборка дала значительно меньший CPU. Это свидетельство зависимости от состояния интерфейса/фокуса, но не окончательное установление причины. Требуется профилировать активное окно; оптимизация высокого foreground CPU ещё не завершена. Новых изменений кода в этом измерительном проходе нет.

Предыдущий синтетический замер на недоступном интерактивном desktop не представлял реальную нагрузку активного окна. Его 0,174% нельзя выдавать за подтверждённый foreground-расход рабочего приложения. Фон в установленной сборке низкий, однако высокий CPU активного окна воспроизводится.

В конце настройки закрыты, главное окно скрыто в трей. Cliptiq продолжает работать. Сырые отсчёты находятся в `experiments/windows-idle/results/2026-11-13-installed-unlocked/`. Команда измерения: `python experiments/windows-idle/measure-running.py --pid <PID> --scenario <name> --seconds 60 --settle 10 --output <path>`.
