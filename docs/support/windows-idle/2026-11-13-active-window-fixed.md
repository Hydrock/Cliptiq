# CPU активного окна: исправление цикла ожидания

13 ноября 2026. Установлена Windows-сборка из коммита `90debb3`, SHA-256 `cdb86f8853237191b946e6ed34ae646c1a42a9aa1c7a0d99935e99fad0f68dcb`, размер EXE 2 334 720 байт (2,23 МиБ). Прежняя сборка и резервная копия истории сохранены в `%LOCALAPPDATA%/Cliptiq/backups/active-cpu-*`. Профиль, настройки LAN и ключи не заменялись. После проверки приложение оставлено в трее.

## Причина и изменение

Старый цикл PeekMessage/MsgWaitForMultipleObjectsEx просыпался от неочередных системных запросов, хотя обычных сообщений для удаления не было. Временные счётчики фиксировали тысячи пустых проходов; адресные стеки показали UIAutomationCore/Oleacc во время PeekMessage. Изменение визуальных метаданных списка и удаление дополнительной проверки очереди этого не устраняли.

Теперь простой ожидается через GetMessage: он обслуживает синхронные межпоточные запросы и продолжает ждать очередного сообщения. Приватный таймер сохраняет существующий срок обслуживания контроллера до 100 мс. Очередь обрабатывается ограниченными порциями; единый диспетчер сохраняет диалоговую навигацию и обработку Enter/Escape при переименовании сниппетов. Изменение относится к Windows; macOS в этом проходе не собиралась. Диагностические счётчики в установленную сборку не включены.

Регрессионный тест отправляет реальные межпоточные SendMessage: на старом цикле он падает с `Idle menu spins on nonqueued cross-thread requests`, на новом проходит. Дополнительно проверены очередь из 130 сообщений, PostMessage, Enter, Tab из фильтра, выделение текста, предварительная обработка редактором и маршрутизация отдельного диалога. Независимый обзор не выявил P1/P2 замечаний.

## Замеры установленного приложения

Windows 11 x64, 32 логических CPU; настоящий профиль с 30 записями и включённым LAN. Каждый интервал — 30 секунд после 5 секунд ожидания, отсчёты раз в секунду. CPU выражен в процентах **одного логического ядра**, а не всей машины. Working set включает разделяемые резидентные страницы; private bytes — приватный commit. Эти две величины не складываются.

Измеритель не читает содержимое буфера и не переключает фокус; каждый отсчёт проверяет foreground PID и числовой ID контрола. Сборка, CTest и сбор стеков одновременно с этими замерами не выполнялись. Ревизия истории до/после — 303, число записей — 30.

Файл `focus-preview-warm.json` сохранил первоначальное название сценария, но фактический ID фокуса во всех отсчётах был 0: в таблице он честно указан как окно, а не предпросмотр. Повтор предпросмотра выполнен отдельно с подтверждённым ID 7195. Все интервалы, включая стартовые всплески и более высокие повторные значения, сохранены.

Ранее на установленной сборке `28888aa` активное окно потребляло 12,630% ядра за 60 секунд. Сейчас подтверждённые интервалы дали 0,104–3,385%: постоянное вращение устранено, однако остаточные всплески активного окна остаются, особенно в предпросмотре. Разные длительности и последовательность фокуса не позволяют считать это строгим парным бенчмарком. Нельзя утверждать, что CPU любого активного контрола всегда ниже 1%. Фоновый расход сохранился низким. Холодные 16,84 МиБ нельзя напрямую сравнивать с прежним прогретым фоном; после открытия/закрытия окна текущий working set — 29,01 МиБ.

## Проверки

Полная пересборка доступных целей успешна. CTest: **61/61 доступный тест прошёл**, 110,66 секунды. Из общего набора 73 исключены 12 известных ограничений среды: `editor_native`, `hotkeys_native_boundary`, `settings_native`, `lifecycle_ui_ru`, `hotkeys_native`, `paste_native`, `menu_regression_keyboard`, `menu_regression_dpi`, `menu_regression_context`, `menu_native`, `windows_clipboard` (CreateWindowStation: Access denied 5), `update_authenticode` (проверка доверия CRT). Это не утверждение о прохождении всех 73 тестов. Проверка локализации: 399 ключей, 9 языков, 952 строки. Python измеритель прошёл py_compile.

Сырые результаты: `experiments/windows-idle/results/2026-11-13-active-window-fixed/`. Адресные стеки — диагностические выборки, а не CPU-weighted ETW-профиль; без PDB надёжна принадлежность модулю, имена ближайших exports не доказывают конкретную внутреннюю функцию.
