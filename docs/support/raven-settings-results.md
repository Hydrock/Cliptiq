# Windows: эксперимент Raven / NativeSettings

Дата: 12 ноября 2026. Ветка `experiment/raven-settings`, исходная ревизия
Cliptiq `a177ae6a42c1cea5f11d331060c3445e9bfc4689`.
Raven 0.2.3, pinned commit `9f0cfa6fe3da33022a577e06a6ea843a5ef3f76e`.

## Что построено

Два самостоятельных приложения настроек, общий host и существующая модель
Cliptiq (54 поля / 8 групп). Native напрямую компилирует существующий
`platform/windows/Settings.cpp`, Raven строит форму через C API. Исходники
рабочего NativeSettings и основного приложения не изменены. Подключение
эксперимента в root CMake выключено по умолчанию.

В обоих вариантах Apply валидирует и сохраняет изолированный SQLite profile.
Регистрация hotkeys/autostart, clipboard monitoring, updates и OCR не запускаются.
Переключатели представляют значения модели, не активные системные службы.
Это UI spike, не перенос полного окна в основной event loop Cliptiq.

Windows 11 build 26200, MSVC 19.51.36247 x64, CMake 4.3, MinSizeRel, static CRT,
IPO/LTO, function-level linking и dead-code elimination. Raven static, web/tools/
examples/tests OFF, Vulkan ON, штатные worker/render threads, Windows Light,
анимации OFF. Сторонний код не изменялся. Vulkan-Headers v1.3.290.

Машина: AMD Ryzen 9 9950X3D, 16 ядер / 32 логических CPU. Перечень адаптеров:
NVIDIA GeForce RTX 4090 (driver 32.0.16.2101), AMD Radeon Graphics
(32.0.21045.16010), Meta Virtual Monitor (5.3.57.114). Конкретный выбранный
Vulkan adapter библиотекой в этом стенде не записывался.

## Результаты

Пять процессов каждого варианта на обычном интерактивном desktop, с чередованием
порядка. В каждом процессе 3 с стабилизации, 10 с idle, затем 3 пересоздания формы.
Профили `:memory:`. Медианы; память в MiB = 1048576 байт.

| Метрика | Win32 NativeSettings | Raven |
|---|---:|---:|
| Процесс → ready JSON, мс | 167.58 | 417.90 |
| Первое создание + первый UI dispatch/submission, мс | 132.79 | 398.77 |
| Пересоздание формы в том же процессе, мс | 199.63 | 90.45 |
| Working set, MiB | 19.37 | 148.21 |
| Private commit, MiB | 3.41 | 181.43 |
| Idle CPU, % одного логического ядра | 9.22 | 1.25 |
| EXE, байт | 1067008 | 2250240 |
| Пакет с инструкциями/лицензиями/manifest, байт | 1081055 | 2300590 |
| ZIP полного пакета, байт | 594241 | 1221635 |

CPU измерен GetProcessTimes: 100% соответствует одному логическому ядру.
При нормализации на все 32 CPU медианы приблизительно 0.288% / 0.039%.
Диапазоны отдельных idle-прогонов: Native 7.81–17.81%, Raven 0.62–1.87%
одного ядра. Неожиданная активность Native в обычном desktop требует отдельного
профилирования: это результат данного host/сеанса, не доказанное потребление
фонового Cliptiq. Короткий предварительный sandbox-прогон давал иной CPU;
смешивать его с этой серией нельзя.

Первое открытие — **ориентир до первого UI dispatch/submission, не до
первого показанного пикселя**. Асинхронный Vulkan present может завершиться позже.
Файловый/shader cache ОС не очищался, холодная загрузка системы не измерялась.
Для frame-accurate сравнения нужен отдельный present/ETW или видеозамер.
Повторное открытие пересоздаёт форму, а не показывает сохранённое окно.
Raven сохраняет runtime, шрифты и renderer между пересозданиями.

Память GPU и системных служб не включена. Размер системного Vulkan driver не
включён в пакет. PE imports обоих EXE проверены dumpbin: только системные DLL,
MSVC runtime DLL не требуются. Raven загружает Vulkan динамически.

## Проверка работоспособности

- Оба варианта собраны MSVC и прошли запуск/завершение с измерителем; итоговая
  серия прошла все 10 процессов и 30 повторных открытий.
- Raven визуально проверен на рабочем столе: General и Excluded, текстовые
  поля/переключатели, переход вкладки мышью.
- Неверный History count=0 отклонён с `Setting out of range`.
- Apply записал History count=37 и `Тест.exe\nexample.exe` в отдельную БД.
  Значения подтверждены read-only SQL, revision=2. После перезапуска UI показал37.
- Native из готового пакета открыт и визуально проверен. Это исходная Win32 форма.
- Полная ручная приёмка клавиатуры, IME, screen readers, DPI/мониторов и всех
  полей не выполнена. UI Automation возвращает дерево Raven; действие по
  виртуальному tab item не переключило вкладку, обычный координатный клик
  сработал. Полную accessibility-совместимость это не подтверждает.
- В предварительной серии произошёл единичный сбой публикации отчёта во время
  повторного открытия (сохранился `.tmp`); точный Win32 error в той сборке не
  логировался. После добавления диагностики 32 пересоздания прошли успешно.
  Измеритель дополнительно переведён на неизменяемые файлы для каждого открытия,
  чтобы исключить замену JSON во время чтения Windows. Сбой не выдаётся за
  подтверждённый дефект Raven; исходная причина окончательно не доказана.

## Вывод

В этом эксперименте Raven примерно в3 раза медленнее при первом создании,
в2.2 раза быстрее при пересоздании прогретой формы и требует около7.7 раза
больше working set. EXE и ZIP приблизительно в2.1 раза больше. По памяти и
стоимости первого открытия переход ради максимальной экономичности не оправдан.
Преимущество общего UI-кода и внешнего вида можно оценить вручную; CPU отдельно
профилировать перед выводами об энергопотреблении. Прогрев Raven при запуске
перенесёт стоимость инициализации, но не устранит её.
