Regression was red before the addition and green after it.

## macOS

Existing packaging installed unstripped code before signing. On ARM native OCR, CI43799890809 measured original executable3003144B, single-binary ZIP1202539B; strip -x copied executable2341208B, ZIP1104360B. This saves661936 raw bytes and98179 ZIP bytes, but is insufficient by itself for the original OCR ZIP gate987169B. strip -S alone saved no raw bytes.

Apple documents strip -x as removing non-global symbols while preserving external symbols: https://developer.apple.com/documentation/xcode/build-settings-reference . This does not remove machine code or features. Only staged copies are candidates for processing before signing; original build outputs remain available. Packaging must still verify the signature, run --version, validate dependency closure, and pass the original size gate.

## Reconnect test prerequisite

The macOS URL/history-only E2E failure after a settings save was a directional HELLO readiness problem in the test. A deterministic real-TLS regression proves that one endpoint may receive HELLO while the sender lacks a live recipient; offline events intentionally do not replay. Both Debug and MinSizeRel TLS/E2E passed locally; production transport code is unchanged.

## Isolated SQLite JSON SQL toggle

The app uses its own validated configuration encoding and opaque clipboard storage, not SQLite JSON SQL functions. Public app/core operations, schema migrations, tests and FTS queries contain no JSON SQL calls. SQLITE_OMIT_JSON removes those unused SQL functions; it does not parse, discard or change clipboard/settings JSON bytes. A persistence regression covers valid JSON MIME data, malformed JSON with NUL/0xff, settings strings and reopening the database. Baseline and candidate history suites both passed, including existing UTF16 cases.

## Adopted SQLite profile and scheduling

After typed-API/schema review and the isolated tests/benchmark above, the production SQLite target now privately defines SQLITE_OMIT_JSON. No other OMIT candidate is adopted. The dependency manifest records json_sql=false without changing the pinned download or source hashes. The core README scopes compatibility to application-owned schemas; arbitrary custom SQL JSON-based triggers/indexes are not promised. A fresh reconfigure/build of the production-profile benchmark and history test passed, and runtime sqlite3_compileoption_used reports JSON SQL omitted while the benchmark remains correct. Source benchmarks now emit that actual profile field for audit. Compiler optimization/visibility defaults are still unchanged.

Core/footprint/size-experiment workflows coalesce repeated push runs by workflow/ref. Explicit manual validation uses independent groups. The latest run retains every functional, size and security check, and token permissions are unchanged. Older runs that started before this configuration do not acquire the group retroactively.
