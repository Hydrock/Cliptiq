# Package size and Pango investigation, 2026-11-16

Branch: feature/windows-workspace. The user explicitly requires the original size baseline to remain unchanged. No LAN/security/functionality removal is accepted as a size fix.

## Linux Pango

Settings help typography directly uses Pango. The exact distribution-provided SONAME libpango-1.0.so.0 was missing from the Linux OS dependency classification. Added only that name; unknown private names, alternate ABI versions and path-prefixed names still fail. Runtime DEB dependencies continue to be generated by dpkg-shlibdeps. Regression was red before the addition and green after it.

## Windows matched scope

Same compiler/environment, MinSizeRel, static CRT, IPO, exceptions and RTTI. Both diagnostic packages retained the identical manifest and all licenses. The LAN-OFF build was diagnostic only and is not a shipping/CI configuration.

Global /Gy /Gw and extra ICF passes made no size difference. Disabling RTTI, disabling inlining and sharing exception conversion produced only small gains; those source/compiler experiments are not adopted. Functional verification for these discarded variants was limited and is recorded honestly in raw evidence.

## macOS

Existing packaging installed unstripped code before signing. On ARM native OCR, CI43799890809 measured original executable3003144B, single-binary ZIP1202539B; strip -x copied executable2341208B, ZIP1104360B. This saves661936 raw bytes and98179 ZIP bytes, but is insufficient by itself for the original OCR ZIP gate987169B. strip -S alone saved no raw bytes.

Apple documents strip -x as removing non-global symbols while preserving external symbols: https://developer.apple.com/documentation/xcode/build-settings-reference . This does not remove machine code or features. Only staged copies are candidates for processing before signing; original build outputs remain available. Packaging must still verify the signature, run --version, validate dependency closure, and pass the original size gate.
