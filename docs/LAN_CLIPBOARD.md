# Общий буфер обмена Cliptiq: первая версия

Функция находится в **Настройки → Ещё → Расширенные настройки LAN**.
По умолчанию устройств нет и сетевой обмен выключен. Открытие формы и редактирование
черновика не запускают сеть. Изменения применяются кнопкой «Сохранить».

## Два компьютера

1. Установите сборку с LAN на оба устройства. Задайте понятные имена.
2. В «Адрес прослушивания» укажите **собственный IP** компьютера в домашней сети
   или VPN, например Tailscale. Начальное значение `127.0.0.1` подходит только
   для тестирования на одном компьютере. Здесь нужен числовой IPv4/IPv6.
3. Оставьте порт `49731`, если он свободен. На другом компьютере порт может отличаться.
4. Добавьте устройство: имя для истории, IP или DNS-имя **второго компьютера**,
   его порт. Имя может быть именем из Tailscale/MagicDNS, если ОС его разрешает.
5. Нажмите «Создать ключ» на одном компьютере. Передайте ключ второму устройству
   по доверенному каналу и введите в обратную запись. Для одной пары нужен один
   и тот же ключ на обоих концах. Каждая следующая пара получает отдельный ключ.
6. На втором компьютере добавьте обратную запись с адресом первого. Сохраните
   настройки на обоих. Дождитесь статуса подключения TLS 1.3.
7. Скопируйте **новый** текст, ссылку или изображение. Он появится в истории
   второго компьютера с подписью устройства и станет его текущим системным буфером.
   Вставьте обычным Ctrl+V или Cmd+V. Автоматическое нажатие вставки при получении
   не выполняется.

Cliptiq не изменяет брандмауэр. Если соединение не устанавливается, проверьте
адрес, порт, ключ пары, VPN-маршрут и разрешение входящего TCP в вашей сети.
Не публикуйте порт через маршрутизатор: для удалённой работы используйте VPN.

## Три устройства и больше

Настройте каждую пару напрямую: A↔B, A↔C, B↔C. Полученные копии не пересылаются
третьему устройству. Автоматического поиска устройств, центрального сервера
и облачной учётной записи нет. Поддерживается до 16 соседей на устройство.

## Управление

- «Принимать только в историю»: не заменять системный буфер полученными копиями.
  По умолчанию выключено: получение идёт и в буфер, и в историю.
- «Отправлять» и «Принимать» управляют направлениями для отдельного устройства.
- Текст, ссылки и изображения можно выключать независимо.
- «Приостановить обмен» останавливает сетевой сервис. Выключение или удаление
  последнего активного устройства также закрывает слушатель и рабочий поток.
- Пустое поле ключа сохраняет существующий ключ; сохранённый ключ не отображается.
  Для замены создайте новый ключ и обновите оба конца пары.
- Подпись источника — имя, которое вы задали этому соседу на принимающем устройстве.

Копирование ключа из формы помечено как временное/скрытое и исключено из истории
и LAN-передачи. Ключ хранится в Windows Credential Manager, macOS Keychain или
Linux Secret Service. Если системное хранилище недоступно/заблокировано, открытого
файла с ключами и нешифрованного сетевого запасного режима нет.

## Что передаётся и какие ограничения

Передаются только новые успешно сохранённые локальные копии: текст UTF-8,
списки URL и PNG. Исходные изображения перекодируются системным кодеком без
уменьшения до миниатюры. Файлы, HTML/RTF, сниппеты и старая история не передаются.
Известные скрытые и временные форматы исключены; содержимое обычного текста
приложение не анализирует на наличие паролей. Включайте обмен только с доверенными
устройствами. Удаление локальной записи не удаляет уже полученную копию у соседа.

Одна передача ограничена 8 МиБ, изображение — 8 миллионами пикселей и стороной
8192. Суммарные транспортные очереди ограничены 16 МиБ (8+8); при занятом канале
ожидает только последняя новая локальная копия. После разрыва старый сетевой
хвост не воспроизводится. Это общий текущий буфер, а не резервное копирование.
При задержке интерфейса история сохраняется, но очередь замены системного буфера
может пропускать промежуточные записи и оставлять последнюю.

TLS 1.3 использует случайный 256-битный ключ пары и эфемерный P-256, AES-128-GCM.
После первого аутентифицированного подключения закрепляется ID соседа. Другой ID
с тем же ключом отклоняется; для переподключения переустановленного устройства
замените ключ пары. Повторы событий отсеиваются в базе. Неудачные подключения
повторяются с задержкой до 30 секунд и небольшим случайным разбросом.

Если во время получения вы сделали локальную копию, Cliptiq сохраняет полученное
в истории и старается не заменять более новый буфер. На Windows проверка выполняется
под блокировкой OpenClipboard. На macOS/Linux проверка непосредственно перед
записью остаётся best effort: публичного атомарного compare-and-set у этих API нет.

## Сборка и проверка

Сначала выполните `python tools/fetch-lan-deps.py`: скрипт получает Mbed TLS
3.6.7 с официального релиза и проверяет закреплённый SHA-256. Конфигурация CMake
сама ничего не скачивает. `python tools/fetch-lan-deps.py --verify-only` проверяет
локальные исходники без сети. Параметр CMake `CLIPTIQ_LAN_SYNC=OFF` собирает
приложение без транспорта и страницы LAN.

Windows: `powershell -ExecutionPolicy Bypass -File experiments/windows-idle/build.ps1 -BuildDir out/windows-lan -Tests -Targets all`.
Тесты: `ctest --test-dir out/windows-lan --output-on-failure -R lan`.
Полезные проверки: `lan_core`, `lan_service`, `lan_tls_transport`, `lan_dns`,
`lan_end_to_end`, `lan_secrets`, на Windows также `lan_settings_native`.
`CLIPTIQ_TEST_NATIVE_SECRETS=1` включает реальный CRUD временного случайного ключа
в системном хранилище; обычный тест не меняет сохранённые ключи.

База автоматически мигрирует со схемы 2 на 3. Перед проверкой на своей истории
сделайте согласованную SQLite backup при закрытом приложении. Старая версия
приложения схему 3 не открывает; для отката нужна копия базы до миграции.
Не запускайте разные версии одновременно на одной базе.

Сборка и реальные loopback TLS-проверки выполнены на Windows. Нативные реализации
macOS/Linux добавлены, но в этой среде не собраны и не запущены. Перед релизом
нужна проверка на настоящих системах, между ОС и по реальной LAN/VPN.
