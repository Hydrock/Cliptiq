# Settings and global shortcuts (T09)

`Settings` is an explicit snapshot of typed, validated preference strings and optional `KeyChord`s, plus a settings revision. `load_settings(Store&)`, `save_settings(Store&, Settings)` and `apply_settings(Store&, HotkeyRegistry&, Settings)` return typed errors. SQLite `settings` keys are namespaced `t09.*`, schema version 1; unrelated settings remain intact. Load uses a bounded read transaction, rejects corrupt/unknown/future schema, never silently resets it. Save uses BEGIN IMMEDIATE, revision compare-and-swap, atomic replacement and retention pruning, then increments the shared history/menu revision. A stale window must reopen settings before applying again.

`apply_settings` acquires changed native registrations before saving/releasing old ones. OS conflict, persistence Result failure or exception frees candidate registrations and keeps previous bindings. Memory for registry commit is prepared before side effects. Unchanged preferences do not re-register existing shortcuts. Cross-action swaps require a temporary free chord. An unavailable backend may save preferences, explicitly without claiming registration. Folder routes use existing T02 IDs; deletion/disabled availability releases registrations. T10 CRUD and enabled-folder storage are not introduced.

## Defaults and validation

Eight native groups: General, Menu, Types, Excluded, Shortcuts, Updates, Beta, Donate. General defaults: history30, last-used sort, duplicates/replacement/confirmation on, cleanup/clear-on-quit off, auto-paste on. Menu: inline0, folder10, title20, numbered from1, numeric selection off, tooltips200, previews100x32, icons/swatches on. All supported capture types default on except HTML. Exclusion and concealed/remote ignores default off. Plain modifier is Command on Mac, Ctrl elsewhere; delete/paste-delete are disabled. Bounds and fixed cleanup intervals match the source audit; unsupported future features cannot be enabled by editing the database.

Mac shortcuts retain Command+Shift+V (main), Command+Control+V (history), Command+Shift+B (snippets), all four modifiers+V (Settings). Windows/Linux propose Ctrl+Alt+V/H/B and Ctrl+Alt+Shift+V for Settings. Editor/clear/folder shortcuts default unset. Settings cannot be unset. Editor opens Settings with a T10-unavailable reason. Clear uses the configured confirmation policy; snippets and current clipboard are retained.

A chord uses explicit modifier bits Control1/Shift2/Alt4/Super8, a letter/digit/F1-F11, and `KeyMeaning::Logical` or `Physical`. Logical serialization is `Ctrl+Alt+V`; physical is `@55:Ctrl+Alt+V`, where55 is platform-native code, not portable across OSes. Windows rejects physical bindings because RegisterHotKey uses VK semantics. No naked/Shift-only keys, duplicate actions/chords, Win+V or F12 are accepted. UI recorders record logical chords; physical representation is an explicit lower-level contract. OS-reserved combinations can still fail with a visible error. Recorders consume an already registered global chord only while the Settings window is active/key and its shortcut field is focused.

## Native services

- macOS: AppKit tabs/scroll views, Carbon RegisterEventHotKey, ASCII-capable logical mapping. No new bundled framework. Actual layout transitions, real keyboard activation and permission UX remain manual gates.
- Windows: Win32 tabs with independently scrolling child pages, resize layout and keyboard focus reveal; recorder handles normal and system-key events (Alt). RegisterHotKey/MOD_NOREPEAT, unregister on replacement/destruction. Noninteractive station reports Unavailable/Unsupported, not a successful registration. CI station tests verify denial; a separate native-adapter API-boundary fixture scripts registration/conflict/cleanup without global grabs. Real interactive registration/activation remains OPEN.
- X11: GTK notebook/scrolling pages; checked passive XCB grabs for keycode/modifiers and discovered lock masks. Partial grab conflict rolls back. Proactive logical-key remap refresh acquires the new native key before releasing the old while preserving registry IDs. A remapped key occupied by another client remains a visible conflict: choose another free chord. ASCII/Latin logical resolution is explicit; unsupported maps require physical bindings or recovery launcher.
- Wayland: explicit user action authorizes xdg-desktop-portal GlobalShortcuts via async CreateSession/BindShortcuts. Preferred triggers are hints; UI status uses actual returned `trigger_description`, subsets and ShortcutsChanged. Denial retains the previous session; activation requires current session and confirmed action; session/service closure invalidates status. Activation token is carried to invocation context, not treated as input permission. No XWayland/root/uinput fallback, no automatic permission prompt. The private D-Bus peer tests protocol behavior, not real desktop support.

## Host integration and persistence

The review host loads one settings snapshot for capture policy/history retention/menu options/paste modifiers. Apply stops and drains capture, atomically saves/binds, updates live options, restarts capture with the new privacy gate and rebuilds the menu. On failure the old capture configuration resumes. Settings changes made in this window apply live; multiple windows are protected by revision CAS. External-process live reload and single-instance forwarding are not claimed.

Default stores use Cliptiq namespaces: `%LOCALAPPDATA%/Cliptiq/history.sqlite3`, `~/Library/Application Support/Cliptiq/history.sqlite3`, `$XDG_DATA_HOME/cliptiq/history.sqlite3` (or `~/.local/share/cliptiq`). `--database PATH` overrides it; `--capture` still requires explicit database selection. Smoke/demo uses an in-memory store and never registers global keys, reads/writes clipboard or sends input.

CLI/desktop recovery: `--show-main`, `--show-history`, `--show-snippets`, `--show-settings`, `--show-editor`, `--clear-history`, `--show-folder ID`. `platform/linux/cliptiq-shortcuts.desktop.in` is an uninstalled template for desktop custom-shortcut commands. It starts a review-host process; it is not IPC to an existing instance. Final packaging/lifecycle integration is later-stage work.

Future launch-at-login, screenshot watcher, updater/diagnostics and donation integration remain disabled with reasons; no SDK/service/assets are bundled. Auto-paste and type controls also reflect unavailable platform capabilities honestly. Generic Win32 type icons stay disabled per T07; RGBA previews work.
