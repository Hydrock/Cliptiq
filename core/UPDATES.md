# T15 update/diagnostics contract

See [delivery routes and bounded SDK build](../packaging/updates/README.md), [privacy](../docs/support/privacy.md), [measured results](../docs/support/t15-results.md) and [manual acceptance](../tests/manual/updates.md).

`check_update(UpdateProvider&, UpdateChannel, current_version, UpdateTarget)` returns authenticated `UpdateInfo`; `apply_update` validates/re-authenticates immediately before a trusted provider delegates installation. The provider is trusted application code, not an untrusted plugin or a boolean read from the feed. Metadata alone is never authenticity. The supplied base application uses repository metadata only for availability and never sends it to an installer. Sparkle is the supplied optional native installation implementation; real Windows installers/package repositories are distribution inputs, not invented by unit tests.

Version format is strict unsigned canonical MAJOR.MINOR.PATCH, no leading zeros/build/prerelease suffix, components≤UINT32_MAX. Stable hints ignore non-stable tags and choose the highest newer supported version, independent of publish order. Unknown channel/target/route, zero/oversized package, malformed version, unapproved URL or missing signing metadata rejects. Policy-provider tests cover offline/timeout, invalid/missing signature, wrong platform/arch, downgrade, size ceiling, cancellation and no package-managed overwrite. Native Authenticode and SDK CLI fixtures separately exercise real cryptographic verifiers.

Settings keys: updates_auto (default0), updates_interval (86400/604800/2592000, default604800). update.last_attempt is stored outside t09.* so Apply does not reset it; failures are attempts, not success. Future/invalid timestamps fail conservatively. Current version and attempt/status are visible in the menu/settings status. Manual check, download/instructions and local diagnostics export are native menu actions. Windows/Linux workers poll the fixed project Atom feed only on manual action or opt-in schedule; no network by default/smoke. Sparkle owns provider preferences/schedule/last-check and startup does not overwrite them.

Both Sparkle downloader targets compile a SHA-pinned narrow source patch: ephemeral uncached NSURLSession,20s resource timeout,128KiB temporary appcast and5MiB persistent update retained-byte limits, checked before append even for unknown length. Only complete bounded archives are written inside a private exclusive directory. The upstream installer/Ed25519 verification is unchanged. The memory ceiling describes retained application response data, not total NSURLSession/process RSS. A native synthetic transport fixture demonstrates RED with original source and GREEN with bounded source, including a valid response and both oversized modes. A real configured feed/update installation remains manual acceptance.

Portable Windows/Linux unattended installation is not implemented; package-manager files are never overwritten. No hidden update/rollback helper is fetched after installation. Windows optional verification utility inspects trust plus exact publisher certificate pin but never launches code. Production identities, own appcast, signed installers/repositories, actual cancellation/relaunch/rollback and clean-system verification remain OPEN. T16 is excluded.

Local diagnostics are a constant whitelist without Store access; user approved replacing Firebase/Crashlytics. See privacy.md for deliberate service-parity differences.
