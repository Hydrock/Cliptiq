# Optional Clipy migration contract (T14)

`export_clipy_sqlite(source, interchange, optional_settings)` and `import_clipy(Store&, interchange, ImportOptions)` live in the separate cliptiq_migration library. No application target links the converter/Realm. The main app adds only portable replay adaptation in its existing paste path.

The exporter recognizes the pinned Clipy grdb_migrations v1–v4 identifiers/columns. It reads the original DB, WAL and rollback journal as regular binary files into private scratch, verifies a second byte hash and sidecar presence, then opens ONLY the private copy with SQLite for recovery and a read transaction. It never opens source SQLite/Realm in a mode that could create source SHM, upgrade a source file or remove its locks. Quit Clipy first; changing copies are rejected. Reads may update OS access times; the guarantee concerns original content/no source-side writes, not forensic timestamp preservation.

Export is explicit user action and produces the neutral backup; it refuses an existing output and publishes a complete validated database via a same-filesystem hard link. Filesystems without hard-link support fail explicitly. No original file is deleted. A crash can leave private scratch, not a modified original. No secure erasure guarantee is made for SQLite free pages, storage or temporary data after deletion.

Neutral format_version1 uses fixed history/assets/thumbnail/folder/snippet tables plus migration_settings. Native IDs, asset order, enabled states, native types and bytes, times, title/device/types/OCR/thumbnail provenance and exact preferences are retained. Missing createdAt in SQLite v1/v2 and Realm is represented using the original update time; a historical creation date cannot be invented. Folder/snippet positions are normalized for app operations while original index values remain provenance. Duplicate contents with distinct original IDs survive. ID conflicts abort the entire transaction; identical repeated imports are no-ops. Changed sources/conflicting IDs and reimport after explicit deletion require a fresh destination/manual reconciliation.

Destination history, folders/snippets/states, provenance, settings, receipt and revision commit atomically. Existing valid Store content survives errors. CLI may initialize a new empty Store before a failed import. No migration-time history pruning is invoked; normal later capture/cleanup/clear-on-quit follows configured policy. History-derived provenance and original archives have explicit history ownership with ON DELETE CASCADE, including delete, clear, paste-delete, normal pruning and periodic cleanup. Folder/snippet metadata is owned likewise. Global preferences remain settings, separate from clipboard history. Live deletion is not secure erase.

Bounds: source DB/WAL/journal each≤1GiB, normalized payload≤256MiB, representation≤32MiB, history entry≤64MiB,100000 history entries,1000 folders,10000 snippets,4096 parts/entry. Text/title≤1MiB, ID≤1024B, native type≤4096B. Preferences file≤16MiB checked BEFORE read; source growth cannot exceed bounded chunk readers. Inert original legacy entry archives≤64MiB, distinct from the16MiB preference limit. All normalized payload, original archives, settings and thumbnails share the256MiB import budget. Limits are not a claim of RSS≤160MiB; copy/recovery/dataset memory is extra and migration is an offline helper.

Typed scalar/null checks reject malformed timestamps/metadata rather than SQLite coercion. Unknown schemas, views in place of required tables, missing/orphan assets, invalid UTF-8 metadata, invalid states, quotas and late conflicts reject atomically. Unknown or unsupported archive forms/types reject export rather than silently discarding clipboard content.

Settings are inert by default; the exact source plist and recognized original values are retained. --apply-settings activates the validated compatible subset, including explicit nil-disabled shortcuts, type preferences and exclusions; it does not register hotkeys with the OS during import. Login, screenshot watching, update and telemetry are not activated by migration. Unsupported keycode-only/double-modifier/reserved chords retain raw data and require reassignment. Original macOS application identifiers are not translated into Windows executable/Linux desktop identities; exclusions must be reconciled before resuming capture on another OS. The default inactive-settings import avoids implicitly replacing existing policy. Real OS hotkey conflicts remain registration/manual acceptance.

macOS replay reconstructs item indices by each normalized native type's occurrence count; legacy NSFilenamesPboardType stays a root offer. Windows/X11/Wayland adapt supported single-item Unicode text, RTF, HTML, PDF and compatible PNG/TIFF encodings at explicit selection. CF_HTML framing/UTF-16 text conversion use existing native contracts. Original bytes in Store remain unchanged. RTFD, native file references, unknown types and multi-item history do not acquire invented portability. If a supported fallback is copied while some formats are unavailable, the outcome says so; if none is usable or item boundaries cannot be represented, copy fails with originals retained and no history deletion.

The optional macOS Realm helper pins RealmSwift10.54.6/RealmCore14.14.0 in Package.resolved. Only a private copy may undergo Realm file-format upgrade. Only schema7 is supported; no upstream migration callback or deletion of source lock/management is used. Asset basenames resolve inside the explicitly supplied asset directory; missing/nonregular/symlink assets abort. SDK analytics is explicitly disabled before Realm use. No payload network route is configured.

Archive decoding occurs only in optional tools, with explicit inert class mappings and Foundation allowlists. NSImage is mapped to an inert reader: bounded encoded PNG/TIFF is inspected by ImageIO headers for≤40MP; no full NSImage decode/tiffRepresentation expansion occurs. Unrecognized or ambiguous encoded image forms fail safely. Tests include actual Cocoa image archives and oversized declared dimensions. These tests do not prove every historical archive/image representation.

The separate staged migration delivery includes the C++ converter, native preferences exporter, Swift helper, required Realm dylib and notices. Release loader metadata is preserved, debug symbols excluded, and relocation is tested while the build-tree Realm dylib is unavailable. Dependency bytes and complete migration lane are counted separately and together with the app executable. This is not a Developer-ID/notarized installer or proof of a clean-system offline closure.

XML snippets-only fallback is the existing T11 native editor import/export: titles/content/order survive, enabled states/UUIDs/hotkeys do not. T15 is excluded. Manual T04–T13 remain OPEN; T14 personal-backup/clean-system/historical-file acceptance is also OPEN.
