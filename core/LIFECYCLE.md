# Desktop lifecycle contract (T13)

C++17 shared lifecycle/locale layer; existing SQLite, native OS APIs and generated static strings. No service, web runtime, translation framework, bundled daemon or network lookup.

`SessionInstance::start({private_directory, session_scope}, optional_action)` returns Primary or Forwarded. Only Main/History/Snippets/Settings/Editor can be forwarded. Arbitrary paths, executable names, clear/delete and shell commands are not IPC commands. Null action is primary-only. A second process returns a visible error on busy/startup failure rather than claiming delivery. The owner polls every100ms on the existing UI loop; no capture/store is started by a follower. Fixed routes recover Settings even without tray/global shortcut; the native launcher remains available.

Directory is private to the user: POSIX uid +0700, Windows owner/protected DACL without reparse points. Final symlinks and unsafe locks are rejected; verified ancestor paths are canonicalized for SQLite NOFOLLOW (macOS /var temp roots). OS-held owner lock is released on crash. A separate short initialization lock serializes owner election/reset and follower insert, so stale application_id cannot indicate current-owner readiness. Both locks use existing OS primitives. Mailbox is SQLite application_id1129597266, version1; max16 pending integer actions, existing file ≤1MiB, bounded waits (~1s initialization + SQLite busy250ms). Unknown databases are not overwritten. Empty interrupted initialization can recover. A crash after successful forwarding but before receiving can lose that pending UI request; this is not durable exactly-once IPC. Retained requests are cleared at owner restart, protected from newly forwarded actions by initialization lock.

Scope is Windows logon session ID, macOS uid in the private temporary session root, Linux first available XDG_SESSION_ID/Wayland/display/session-bus identifier +uid, hashed for bounded filenames. Linux processes with inconsistent session environment can choose different scopes; test actual desktop launch paths manually. Host database stays the existing configured/default database. T16 multiwriter/index lifecycle is not implemented here.

`Autostart::set_autostart` returns enabled/requires_approval/reason. Settings Apply changes registration only when the login preference changes, snapshots actual registration first, then commits settings. A failed settings commit restores the pre-operation native registration (rather than stale preference); rollback failure is retained as a visible error. Unchanged preference does not silently override externally disabled OS registration. Startup uses readonly inspect; mismatch or approval required is surfaced persistently. Apple approval is controlled by macOS: unregister/re-register cannot guarantee restoration of the exact previous approval grant. A real OS registration action is not attempted by isolated tests.

macOS13+: SMAppService.mainAppService, own Cliptiq.app bundle ID, approval status visible. Windows: current-user HKCU Run Cliptiq value with quoted executable; no administrator privilege or shell. Linux: marked owned XDG autostart desktop file, double-layer executable escaping, atomic replace; refuses unowned/symlink entries. `--remove-autostart` unregisters explicitly before manual removal; future installer/uninstaller must invoke it. No installer/uninstaller is delivered in T13. Changing executable location can leave an old registration; do not claim upgrade/move cleanup acceptance.

Supported routes: `--show-main`, `--show-history`, `--show-snippets`, `--show-settings`, `--show-editor`; `--locale CODE` overrides preference for this process; `--about` shows own version/support; `--background` currently still presents the launcher (known Minor). Main binary defaults to real capture; smoke/test hosts isolate external effects. Windows Cliptiq.exe uses GUI subsystem and UTF-16 command-line conversion; macOS Cliptiq.app has own bundle metadata; Linux installs cliptiq and desktop actions. Actual logout/login, signing, clean-install and assistive technology checks remain manual.

`resources/locales/*.json` is the source of generated `core/src/locale_catalogue.cpp`; run `python tools/generate-locales.py --check` in CI and without --check to regenerate. EN/RU132 keys each; seven partial inherited locales de/fa/it/ja/pt-BR/uk/zh-Hans. Exact locale, then base language, then English per-key fallback. Unknown keys return their English source text. OS auto language: NSLocale, GetUserDefaultLocaleName, Linux LC_ALL/LC_MESSAGES/LANG. Settings change applies next launch. Catalogue activation/lookup is on the UI thread. User clipboard/snippet/folder content is never translated. Technical error diagnostics can stay English; RTL shaping/mirroring, full inherited-locale quality and screen-reader pronunciation are not verified.

Native controls use OS fonts/semantics; GTK labels have mnemonic targets/accessibility names, AppKit labels have accessibilityLabel, Win32 wrapping height uses the active font. RU title/control smoke is automated. This is not WCAG or screen-reader certification, nor proof of200% DPI layout. Third-party translation inventory and notices are committed with source hashes. There is no invented donation endpoint.
