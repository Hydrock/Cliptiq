# Эксперимент: настройки Cliptiq на Raven / Win32

Это отдельные Windows x64 приложения для сравнения UI, не полноценный менеджер
буфера и не production-релиз. Основное приложение не изменено.

## Запуск

Откройте `settings_native.exe` или `settings_raven.exe`. Для ручного сравнения
можно открыть оба; для измерений запускайте `measure.py`, который открывает их
по очереди. Закрытие окна завершает экспериментальный процесс.

Обе формы используют существующие `default_settings`, `settings_fields`,
`edit_settings`, `save_settings` и `load_settings` Cliptiq: 54 поля, 8 групп.
Native использует исходный `platform/windows/Settings.cpp` без модификаций.
Raven строит те же поля средствами Raven и использует общий валидатор.
Поля shortcuts записывают сочетания; Backspace очищает необязательное поле.

Apply сохраняет значения в `profile-native/settings.sqlite3` или
`profile-raven/settings.sqlite3` рядом с EXE. Папка должна быть доступна для записи.
Никакие настройки установленного Cliptiq, системный автозапуск, глобальные
hotkeys, clipboard capture, обновления или OCR прототип не включает.
Переключатели показывают модель настроек, а не фактически работающие службы.
Проверка занятости сочетаний другими приложениями не производится.
Язык интерфейса в этом эксперименте остаётся английским.

Для проверки: измените History count, нажмите Apply, перезапустите EXE и
проверьте значение. Значение 0 должно вызвать ошибку без сохранения.
Проверьте вкладки, многострочные исключения с кириллицей, shortcuts, прокрутку,
масштабирование Windows и клавиатурную навигацию.

Raven требует работающий Vulkan runtime/драйвер видеокарты. VC++ Redistributable,
Python и инструменты разработчика для запуска EXE не нужны. Сборки не подписаны.

## Воспроизведение сборки

Нужны Windows, MSVC x64 Build Tools с CMake/Ninja, Git и Python. Из корня Cliptiq:

```powershell
powershell -ExecutionPolicy Bypass -File experiments/raven-settings/build.ps1 -Fetch
python experiments/raven-settings/package.py
```

`-Fetch` получает Raven и закрепляет коммит
`9f0cfa6fe3da33022a577e06a6ea843a5ef3f76e` (0.2.3), загружает штатную pinned
SQLite с SHA256-проверкой. При первой конфигурации Raven получает Vulkan-Headers
`v1.3.290`. Повторная сборка: та же команда без `-Fetch`.

Оба EXE: MinSizeRel, MSVC static CRT, IPO/LTO, dead-code elimination.
Raven линкуется статически; web, examples, tools и tests Raven отключены.
Настройки renderer/job threads по умолчанию, тема Windows Light, анимации
отключены для сравнения со статической Win32-формой. Второй встроенный renderer
не добавлялся, сторонний код Raven не патчился.

Бинарники: `out/raven-settings/settings-bin/`. Пакеты для передачи:
`dist/raven-settings/`. Там EXE, инструкции, manifest SHA256 и лицензии.
Модели OCR, дизайнер Raven и пользовательские БД в ZIP не входят.

## Методика сравнения

Запускать на незаблокированном Windows desktop, не взаимодействуя с тестовыми
окнами во время измерения:

```powershell
python experiments/raven-settings/measure.py --trials 5 --settle 3 --idle 10 --reopens 3
```

- Пять новых процессов каждого варианта, порядок чередуется. OS/disk/shader
  caches не очищаются: это process-cold, а не доказанный холодный запуск системы.
- `launch_to_ready_ms`: от создания процесса Python до чтения ready JSON;
  включает наблюдение с интервалом 5 мс и публикацию отчёта.
- `first_open_dispatch_ms`: создание формы, включая первую инициализацию Raven,
  до возврата первой обработки/отправки UI-кадра. Это **не время первого
  отображённого пикселя**; асинхронный Vulkan present и Win32 paint имеют разные
  границы. Сравнение является ориентиром, не frame-accurate замером.
- Повторное открытие пересоздаёт форму, как существующий NativeSettings::show;
  Raven сохраняет уже инициализированный runtime. Скрыть/показать готовую форму
  было бы другой оптимизацией и здесь не сравнивается.
- После 3 с стабилизации: CPU за 10 с, working set и private commit процесса.
  100% CPU = полностью занятое одно логическое ядро. Память GPU, системных служб
  и внешних процессов не включена. Нули означают предел разрешения измерения.
- Для исключения дискового профиля оба варианта используют `:memory:`.
  После idle делаются три повторных открытия. В отчёте сырые прогоны и медианы.
- Размер EXE, EXE-only ZIP и полного пакета с notices приведены раздельно.
  Системный Vulkan driver не включён в размер поставки.

Эксперимент оценивает стоимость отдельного окна, не всего Cliptiq. Полная
интеграция потребует совместить event loops, владение фокусом, accessibility,
локализацию и повторную проверку разрешений/системных действий.
